# Stay Concierge

京都の小規模宿泊施設向け、日英対応の静的ゲストガイド試作品。架空施設「京の宿 こもれび」を使用します。

## 現在できること

- スマートフォン向けのレスポンシブ画面、日本語／英語切り替え（URLの `lang` で保持）
- Wi-Fi情報のコピー（HTTPSまたはlocalhostが必要）、案内の検索、FAQの開閉
- 到着前・チェックイン／アウト・設備・ルール・アクセス・お知らせ
- 施設編集：このブラウザにだけ保存、プレビュー、JSON入出力
- `?property=demo` で施設別JSONを読み込み。未知のIDではエラーを表示
- 外部スクリプト、アクセス解析、広告、ゲスト入力フォームなし

**未実装**：スタッフ認証、共有DBへの保存、施設別の権限管理、課金、QR画像の生成、問い合わせ送信、自動翻訳、オフライン保証。編集画面は認証付き管理画面ではありません。プレビューは別端末に共有できません。

## 開発・確認

Node.js 22以上。外部依存パッケージはありません。

```sh
npm test
npm run build
python3 -m http.server 8080 --directory dist
```

`http://localhost:8080` を開きます。`file://` ではJSONを読み込めません。

## Cloudflare Pages

既存の `nmzfc1213-hub/stay-concierge-demo` に変更を反映後、既存Pagesプロジェクトの設定を確認します。別プロジェクトを勝手に作成しないでください。

- 本番ブランチ：`main`
- フレームワーク：なし
- ビルドコマンド：`npm run build`
- 出力ディレクトリ：`dist`
- 環境変数、Functions、D1：この試作品には不要

Cloudflare画面で `Workers & Pages` → 対象プロジェクト → `Deployments` を開き、最新のコミットと成功状態、公開URLを確認します。既存設定がルート配信の場合、`index.html` は表示できますが、上記ビルド設定へ合わせることを推奨します。`_headers` はPages配信時に適用されます。

## 施設情報を更新する

1. フッターの「施設設定プレビュー」で日英を編集します。
2. 「端末に保存」→「プレビュー」で内容を確認します。公開には反映されません。
3. 「JSONを書き出す」。iPhoneはSafariのダウンロード／ファイルAppに保存します。
4. 確認したデータを `data/<施設ID>.json` として対象リポジトリへ保存し、デプロイします。
5. `https://<確認済みの公開先>/?property=<施設ID>&lang=en` を別端末で確認します。

施設を追加する場合は `data/demo.json` をコピーし、`id` と日英の全項目を変更します。固定クイックリンクのため、`arrival`、`facilities`、`access`、`faq` のカテゴリーIDは維持します。時刻は要約欄と本文の両方を更新してください。編集プレビューは常にデモ表示です。実施設が全内容を確認してから、リポジトリ内のデータの `demo` を `false` に変更します。自動的に本番へ切り替わる仕組みはありません。

## 情報管理

公開リポジトリのJSONは誰でも閲覧できます。Wi-Fiは公開可能なゲスト用ネットワーク情報だけを扱い、施設の判断で掲載します。鍵の暗証番号、ゲスト氏名・予約番号、スタッフ用パスワード、APIキーは保存しないでください。案内ページを非公開にする認証機能はありません。ブラウザ保存は端末の操作で消えるためJSONで保管してください。

## 商品化の次工程

施設間のデータ分離を伴う認証とサーバー保存、監査履歴、バックアップ、更新・復旧手順、実施設での日英内容確認、iPhone/Android実機テストが必要です。D1/Functionsを採用する場合は、先にCloudflareアカウントのプラン・料金・利用制限を確認し、費用を説明した上で設定してください。このリポジトリは課金済み商品や運用中のSaaSではありません。
